# AI 協同開發與維護規範 (AGENTS.md)

本規範適用於所有參與此專案之 AI Agent（包含 Antigravity、Claude Code、Codex 等）。所有 Agent 必須嚴格遵循本規範以確保專案一致性、可重現性與資料安全。

---

## 1. 核心工作原則

1. **工作交接與進度提醒機制**：
   - 每次開啟本檔案夾或接收新任務時，Agent **必須主動提醒**：
     - **上次處理進度**（參考 `PROJECT_STATUS.md` 之紀錄）
     - **本次接續進度**（當前即將進行之任務項目）
2. **文件同步更新原則**：
   - **每次任務結束後**：必須更新 [PROJECT_STATUS.md](file:///C:/Users/User/Desktop/115學年度/11502%20信託/PROJECT_STATUS.md)。
   - **新增、刪除、改名檔案時**：必須即時更新 [README.md](file:///C:/Users/User/Desktop/115學年度/11502%20信託/README.md) 之檔案結構說明。
   - **改變工作流程、工具鏈、資料來源、公式規則或 Agent 準則時**：必須同步更新本檔案與 [CLAUDE.md](file:///C:/Users/User/Desktop/115學年度/11502%20信託/CLAUDE.md)。
3. **資訊不足時之應對**：
   - 使用合理專業假設，並在 `PROJECT_STATUS.md` 中詳細記錄「待確認事項」。
4. **原始資料保護**：
   - **絕對不要覆蓋或竄改原始檔**（如 `JY電子檔筆記-信託業務-V8.6.0.pdf` 與 `JY電子檔筆記-信託業-專案檔.docx`）。
   - 保留原始資料，確保所有分析結果可溯源、可驗證、可重現。

---

## 2. 格式與技術規範

1. **語系要求**：所有對外說明、註解、文件與輸出成果一律使用**繁體中文**。
2. **數學公式規範**：
   - **Markdown 文件**：一律使用 LaTeX 語法（如 `$E = mc^2$` 或 `$$...$$`）。
   - **Word 文件**：一律使用 Office Math / OMML 格式，確保方程式可無失真編輯。
   - 必要時保留兩者轉換對應規則。
3. **編程與資料分析**：
   - Python 程式碼遵守 PEP 8，附型別標註與繁體中文 docstring。
   - 避免前視偏誤（Look-ahead bias），資料切分與回測邏輯須清晰分離。

## 3. 學術研究與實證規範（若專案涉及學術論文）

若本專案延伸至學術研究或 SSCI 期刊發表，必須嚴格依循：
1. **文獻創新與差異化**：
   - 檢索 Google Scholar 國際頂級期刊文獻，確認研究議題之理論缺口（Gap）與邊際貢獻（Marginal Contribution）。
2. **樣本與資料來源**：
   - 優先採用公開、權威之官方資料庫（如金管會銀行局、信託公會、TEJ、公開資訊觀測站）。
   - 明確標註樣本期間、篩選條件與極端值處理方式。
3. **變數處理與資料整合**：
   - 每份原始資料單獨儲存為獨立檔案。
   - 撰寫清洗與合併腳本，整合成完整面板（Panel Data）或時間序列資料檔。
4. **實證分析與可重現性**：
   - 實證模型提供完整之 R 語言 / Python 程式碼，包含多變量迴歸、穩健性檢驗（Robustness checks）與內生性處理（Endogeneity）。
5. **研究結論價值**：
   - 清楚闡述實證意涵是否足以支持高水準學術發表或政策建言。

每當本專案製作新網站、產出網頁互動模型、或推播至 GitHub 儲存庫後，必須遵守：
1. **主動詢問使用者**是否整合進 Master Portal 總入口網站（`master-portal`）。
2. **引導確認**：歸屬主類別為 `sem11502`（11502 學期專區），並設定項目編號、標題、副標題、簡述與資源網址。
3. **同步推播與驗證**：更新 `master-portal` 相關索引，推播至 GitHub Pages 並驗證部署狀態。
